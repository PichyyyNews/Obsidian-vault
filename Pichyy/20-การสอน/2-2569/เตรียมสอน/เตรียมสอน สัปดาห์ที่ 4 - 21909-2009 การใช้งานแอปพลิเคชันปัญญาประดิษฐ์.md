## 1. จุดประสงค์การเรียนรู้

เมื่อจบคาบนี้ผู้เรียนสามารถ

- [ ] อธิบายได้ว่า Chain-of-Thought (CoT) คืออะไร และทำไมจึงช่วยให้คำตอบแม่นขึ้น
- [ ] เขียน zero-shot CoT และ few-shot CoT ได้
- [ ] บอกได้ว่าเมื่อไรควร / ไม่ควรใช้ CoT
- [ ] แยกความต่างของ role `system` / `user` / `assistant` ได้
- [ ] เขียน System Prompt ที่มี 6 องค์ประกอบได้ (WHO/GOAL/AUDIENCE/RULES/FORMAT/FALLBACK)
- [ ] ทดสอบ System Prompt ด้วย test case 4 ข้อได้
- [ ] อธิบายข้อจำกัดของ AI อ่านภาพ และลดความเสี่ยงได้
- [ ] รวม CoT + System + Multimodal เป็น workflow เดียวได้

### 2.2 รายละเอียดกิจกรรมแต่ละคาบ

**คาบที่ 1 — ทำไม AI ต้อง "คิดก่อนตอบ" (60 นาที)**

| ขั้น | กิจกรรม | หลักฐานการเรียนรู้ |
| :--: | :--- | :--- |
| 1.1 | ถามทั้งห้อง: "ท่อ A 6 ชม. ท่อ B 4 ชม. เปิดพร้อมกันกี่ ชม." ให้ทุกคนตอบลงกระดาษ โดยยังไม่ใช้ AI | คำตอบรายคน (ส่วนใหญ่ตอบ 10 หรือ 5) |
| 1.2 | เปิด AI 2 ครั้ง: ถามสั้น ๆ vs "ให้คิดทีละขั้นตอน" | เห็นความต่างบนจอ |
| 1.3 | เฉลย: 1/6 + 1/4 = 5/12 → 12/5 = 2.4 ชม. | เข้าใจว่า "ขั้นตอน" เปลี่ยนคำตอบ |
| 1.4 | อธิบายกลไก: โมเดลสร้าง token ทีละตัว → ยิ่งเขียนขั้นตอน = ยิ่งมีพื้นที่คิด | ตอบคำถาม "ทำไม" ได้ |
| 1.5 | ลงมือ: 3 โจทย์คำนวณ (ลด % / / เฉลี่ย / ภาษี) ด้วย zero-shot CoT | สกรีนช็อตผลลัพธ์ |

**คาบที่ 2 — few-shot CoT สู่ System Instruction (65 นาที)**

| ขั้น | กิจกรรม | หลักฐานการเรียนรู้ |
| :--: | :--- | :--- |
| 2.1 | สาธิต few-shot CoT 2 ตัวอย่าง → ให้ทำข้อใหม่ | ผัง "โจทย์–คิด–ตอบ" ในสมุด |
| 2.2 | ให้นักศึกษาใช้ AI ทำโจทย์ที่ตัวเองตั้ง 1 ข้อ แล้วตรวจว่าขั้นตอนถูกหรือแค่ดูดี | ตั้งคำถามจับผิด ≥1 จุด |
| 2.3 | พัก 15 นาที | — |
| 2.4 | สอน 3 roles + 6 องค์ประกอบ (เปิดบทที่ 5 หัวข้อ 3) | จด 6 องค์ประกอบครบ |
| 2.5 | เขียน system prompt ด้วยกัน 1 ชุด (ผู้ช่วยตรวจโค้ด) | prompt บนกระดาน |

## 5. แผนสำรอง

> [!warning] ถ้าอินเทอร์เน็ตล่มหรือ AI ใช้งานไม่ได้
> 1. ใช้ผลลัพธ์ที่พิมพ์เก็บไว้ล่วงหน้า (CoT 3 ตัวอย่าง + system prompt 2 ชุด + ผลทดสอบ 4 ข้อ)
> 2. ให้นักศึกษาเขียน system prompt บนกระดาษ แล้วสลับกันตรวจด้วย checklist 6 องค์ประกอบ
> 3. มอบหมายให้รันจริงที่บ้านแล้วแนบภาพหน้าจอในใบงาน
> 4. คาบที่เหลือสอน **"การอ่านคำตอบอย่างมีวิจารณญาณ"** — ให้ตัวอย่างคำตอบที่ดูน่าเชื่อแต่ผิด 3 ข้อให้จับผิด

> [!note] ถ้าเด็กตามไม่ทัน
> ตัดหัวข้อ 2.6 (unfaithful reasoning) และ 2.7 (reasoning model) ออกก่อน
> ส่วนที่ต้องเก็บให้ครบ: CoT หลักการ + System 6 องค์ประกอบ + ข้อจำกัด Multimodal 3 ข้อ

> [!note] ถ้าเด็กไปเร็วกว่าแผน
> เพิ่มโจทย์ "Self-consistency": ให้ถาม AI 3 ครั้งด้วยถ้อยคำต่างกัน แล้วเทียบคำตอบ
> หรือให้ออกแบบ system prompt 2 ชุดสำหรับงานเดียวกัน แล้วเปรียบเทียบคุณภาพ

## 6. หมายเหตุสำหรับผู้สอน

### 6.1 ภาพตัวอย่างที่ต้องเตรียม (สำคัญ)

| # | ภาพ | ใช้สอนเรื่อง | จุดที่อยากให้เด็กเห็น |
| :--: | :--- | :--- | :--- |
| 1 | หน้าจอ Python error ตัวหนังสือชัด | OCR + วิเคราะห์สาเหตุ | AI อ่านได้แม่นถ้าภาพดี |
| 2 | ภาพเดิมแต่เบลอ/เอียง/มุมเดียว | ข้อจำกัด | AI ยังตอบเหมือนมั่นใจ → ต้องขอความมั่นใจ |
| 3 | ภาพ UI หรือโปสเตอร์ | วิเคราะห์เชิงออกแบบ | ต้องให้เกณฑ์ก่อนวิจารณ์ ไม่งั้นได้คำชมลอย ๆ |

> [!tip] ก่อนสอน 10 นาที
> * เปิด ChatGPT และ Gemini ไว้ 2 แท็บ (สลับเมื่อคิวเต็ม)
> * เตรียม prompt ตัวอย่างในไฟล์ข้อความ เพื่อคัดลอก–วางได้เร็ว
> * ทดสอบอัปโหลดภาพล่วงหน้า 1 ครั้ง (บางห้อง blocked)
> * ตรวจว่าโฟลเดอร์บันทึกงานของนักศึกษาเขียนได้

> [!caution] จริยธรรมที่ต้องพูดทุกคาบ
> ภาพที่อัปโหลดต้องไม่มีเลขบัตรประชาชน เบอร์โทร ที่อยู่ หรือใบหน้าเพื่อน
> และห้ามใช้ AI อ่านภาพเอกสารของหน่วยงานอื่นโดยไม่ได้รับอนุญาต

> [!important] จุดที่เด็กจะสับสนบ่อย
> 1. คิดว่า CoT ทำให้โมเดลฉลาดขึ้น → ต้องย้ำว่าแค่ "มีพื้นที่คิด"
> 2. เขียน system prompt เป็นคำสั่ง "ห้าม..." ล้วน → ต้องบอกว่าต้องทำอะไรแทน
> 3. คิดว่า AI อ่านตัวเลขในภาพได้ 100% → ให้ทดลองกับเลข 8/3 และ 1/l
