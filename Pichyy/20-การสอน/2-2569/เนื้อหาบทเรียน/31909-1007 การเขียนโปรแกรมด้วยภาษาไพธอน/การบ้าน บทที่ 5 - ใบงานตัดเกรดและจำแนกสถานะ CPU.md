## 3. ตอนที่ 1 — โปรแกรมระบบตัดเกรดนักศึกษา ปวส. (10 คะแนน)

### สถานการณ์
อาจารย์ประจำวิชาต้องการโปรแกรมช่วยสรุปผลการเรียนของนักศึกษา โดยต้องตรวจสอบความถูกต้องของคะแนนที่กรอก ตรวจสอบเกณฑ์เวลาเข้าเรียนไม่น้อยกว่า 75% (54 จาก 72 ชั่วโมง) และตัดเกรด 8 ระดับตามระเบียบ ปวส.

### 3.1 ข้อมูลนำเข้า (Input)

| ลำดับ | ข้อมูลที่รับ | ชนิด | เงื่อนไขความถูกต้อง |
| :--: | :--- | :---: | :--- |
| 1 | ชื่อ-สกุลนักศึกษา | `str` | — |
| 2 | คะแนนเก็บ | `float` | ต้องอยู่ระหว่าง `0.0` ถึง `50.0` |
| 3 | คะแนนสอบ | `float` | ต้องอยู่ระหว่าง `0.0` ถึง `50.0` |
| 4 | ชั่วโมงเข้าเรียน (เต็ม 72 ชม.) | `int` | ต้องอยู่ระหว่าง `0` ถึง `72` |

### 3.2 ลำดับการตัดสินใจที่โปรแกรมต้องทำ (Logic Flow)

1. **ด่านที่ 1 — ตรวจสอบความถูกต้องของข้อมูล (Validation):**
   - ถ้า `คะแนนเก็บ < 0 or คะแนนเก็บ > 50` → แสดง `"❌ คะแนนเก็บต้องอยู่ระหว่าง 0–50 คะแนน"` แล้วจบการทำงาน
   - `elif คะแนนสอบ < 0 or คะแนนสอบ > 50` → แสดง `"❌ คะแนนสอบต้องอยู่ระหว่าง 0–50 คะแนน"` แล้วจบการทำงาน
   - `elif ชั่วโมงเข้าเรียน < 0 or ชั่วโมงเข้าเรียน > 72` → แสดง `"❌ ชั่วโมงเข้าเรียนต้องอยู่ระหว่าง 0–72 ชั่วโมง"` แล้วจบการทำงาน
2. **ด่านที่ 2 — ตรวจสอบเวลาเรียนขั้นต่ำ (`else` แล้วใช้ Nested `if`):**
   - คำนวณ `total_score = คะแนนเก็บ + คะแนนสอบ` และ `attend_pct = (ชั่วโมงเข้าเรียน / 72) * 100`
   - ถ้า `ชั่วโมงเข้าเรียน < 54`:
     - เกรด = `"มส."`, GPA = `0.0`
     - สถานะ = `"❌ หมดสิทธิ์สอบ (เวลาเรียนไม่ถึง 75%)"`
     - แสดงว่า **ขาดเวลาเรียนอีกกี่ชั่วโมง** จึงจะครบ 54 ชั่วโมง (เช่น `54 - attend_hours`)
3. **ด่านที่ 3 — ตัดเกรด 8 ระดับ (เมื่อเข้าเรียนตั้งแต่ 54 ชั่วโมงขึ้นไป):**

| ช่วงคะแนนรวม | เกรด | GPA | สถานะ |
| :--: | :--: | :--: | :--- |
| `80.0 – 100.0` | A | 4.0 | ✅ ผ่าน |
| `75.0 – 79.99` | B+ | 3.5 | ✅ ผ่าน |
| `70.0 – 74.99` | B | 3.0 | ✅ ผ่าน |
| `65.0 – 69.99` | C+ | 2.5 | ✅ ผ่าน |
| `60.0 – 64.99` | C | 2.0 | ✅ ผ่าน |
| `55.0 – 59.99` | D+ | 1.5 | ✅ ผ่าน |
| `50.0 – 54.99` | D | 1.0 | ✅ ผ่าน |
| `0.0 – 49.99` | F | 0.0 | ❌ ไม่ผ่าน |

## 4. ตอนที่ 2 — โปรแกรมวิเคราะห์สถานะการทำงานของ CPU (10 คะแนน)

### สถานการณ์
แผนกซ่อมบำรุงคอมพิวเตอร์ต้องการโปรแกรมประเมินสุขภาพ CPU โดย **เกณฑ์ความร้อนที่ยอมรับได้จะเปลี่ยนไปตามโหมดการใช้งานของเครื่อง** (เช่น เครื่องเล่นเกมทนความร้อนได้สูงกว่าเครื่อง Server ที่เปิดตลอด 24 ชม.)

### 4.1 ข้อมูลนำเข้า (Input)

```text
=== เลือกโหมดการใช้งานเครื่อง ===
1. Office / งานทั่วไป
2. Gaming / Render 3D
3. Server (เปิด 24 ชม.)
```

| ลำดับ | ข้อมูลที่รับ | ชนิด | เงื่อนไขความถูกต้อง |
| :--: | :--- | :---: | :--- |
| 1 | โหมดการใช้งาน (`"1"`, `"2"`, `"3"`) | `str` | ใช้ `match-case` ตรวจสอบ (ถ้าไม่ตรงให้แจ้ง Error) |
| 2 | อุณหภูมิ CPU (°C) | `float` | `0.0` ถึง `120.0` |
| 3 | % การใช้งาน CPU | `float` | `0.0` ถึง `100.0` |
| 4 | ความเร็วรอบพัดลม CPU (RPM) | `int` | ต้องมากกว่าหรือเท่ากับ `0` |

> [!note] กรณีเครื่องนักเรียนใช้ Python ต่ำกว่า 3.10
> ให้ตรวจด้วย `import sys; print(sys.version)` — ถ้าต่ำกว่า 3.10 อนุญาตให้ใช้ `if-elif-else` แทน `match-case` ได้โดยระบุ comment แจ้งเวอร์ชันไว้บนหัวไฟล์ แต่ถ้าเป็น 3.10+ **ต้องใช้ `match-case` ในส่วนเลือกโหมด**

### 4.2 เกณฑ์การวิเคราะห์ (ใช้ `match-case` + `if-elif-else` + `and`)

**ขั้นที่ 1: กำหนดเกณฑ์อุณหภูมิตามโหมดด้วย `match-case`**

| โหมดที่เลือก | ชื่อโหมด | เกณฑ์ร้อนมาก (`warn_temp`) | เกณฑ์วิกฤต (`crit_temp`) |
| :--: | :--- | :--: | :--: |
| `"1"` | Office / งานทั่วไป | `75.0°C` | `90.0°C` |
| `"2"` | Gaming / Render 3D | `85.0°C` | `95.0°C` |
| `"3"` | Server (เปิด 24 ชม.) | `70.0°C` | `85.0°C` |
| ค่าอื่น (`_`) | — | แสดง `"❌ โหมดไม่ถูกต้อง กรุณาเลือก 1, 2 หรือ 3"` แล้วจบ | — |

**ขั้นที่ 2: ตรวจสอบความถูกต้องของค่าฮาร์ดแวร์**
- ถ้า `temp < 0 or temp > 120` หรือ `usage < 0 or usage > 100` หรือ `fan_rpm < 0` → แจ้งเตือนค่าไม่ถูกต้องแล้วจบ

**ขั้นที่ 3: จำแนกสถานะ (เมื่อข้อมูลทุกตัวถูกต้อง)**
1. **สถานะอุณหภูมิ CPU** (อ้างอิงตัวแปร `crit_temp` และ `warn_temp` ของโหมดที่เลือก):
   - `temp >= crit_temp` → `"🔴 วิกฤต (เกินขีดจำกัดความร้อนของโหมดนี้)"`
   - `elif temp >= warn_temp` → `"🟠 ร้อนมาก (ควรลดภาระงาน)"`
   - `elif temp >= 55` → `"🟡 เริ่มอุ่น (ปกติค่อนข้างสูง)"`
   - `elif temp >= 30` → `"🟢 ปกติ"`
   - `else` → `"🔵 เย็นผิดปกติ (ตรวจสอบ Sensor)"`
2. **สถานะภาระงาน (% CPU Usage):**
   - `usage >= 95` → `"🔴 โอเวอร์โหลด"`
   - `elif usage >= 80` → `"🟠 ใช้งานหนัก"`
   - `elif usage >= 50` → `"🟡 ใช้งานปานกลาง"`
   - `else` → `"🟢 ใช้งานเบา"`
3. **เงื่อนไขเตือนพิเศษ (Compound Conditions):**
   - ถ้า `fan_rpm == 0 and temp >= 50` → แสดง `"🚨 พัดลมหยุดหมุน! เสี่ยงความเสียหายจากความร้อนสะสม"`
   - ถ้า `temp >= warn_temp and usage >= 80` → แสดง `"⚠️ เตือนพิเศษ: CPU ร้อนและใช้งานหนักพร้อมกันในโหมด <ชื่อโหมด>!"`

### 4.3 ตัวอย่างหน้าตาผลรัน

```text
ความเร็วพัดลม (RPM): 2400

=============================================
📊 รายงานสุขภาพ CPU (โหมด: Office / งานทั่วไป)
=============================================

```

### 4.4 ชุดข้อมูลบังคับทดสอบ (ตอนที่ 2 — ต้องรันครบทั้ง 4 ชุด)

| ชุดที่ | โหมด | Temp (°C) | Usage (%) | พัดลม (RPM) | ผลลัพธ์สำคัญที่ต้องสังเกต |
| :--: | :--: | :--: | :--: | :--: | :--- |
| 1 | `1` | `78` | `85` | `2400` | โหมด Office → อุณหภูมิ **ร้อนมาก** (`>= 75`) + ขึ้นเตือนพิเศษ |
| 2 | `2` | `78` | `85` | `2800` | โหมด Gaming → อุณหภูมิ **เริ่มอุ่น** (`< 85`) + *ไม่ขึ้นเตือนพิเศษความร้อน* |
| 3 | `3` | `65` | `30` | `0` | พัดลม `0 RPM` ขณะ `65°C` → ขึ้นแจ้งเตือน **พัดลมหยุดหมุน!** |
| 4 | `9` | — | — | — | `case _:` จับได้ → แจ้งโหมดไม่ถูกต้องทันทีโดยไม่ถามค่า CPU ต่อ |

> [!tip] สังเกตชุดที่ 4
> ถ้าวางโครงสร้างดี: ใช้ `match-case` ตรวจสอบ `mode` ก่อน — ถ้าเข้า `case _:` ให้แจ้ง Error เลยโดย **ไม่ต้องรับค่า `temp`, `usage`, `fan_rpm`**! ส่วนกรณี `1`, `2`, `3` ค่อยรับค่าฮาร์ดแวร์ต่อ (หรือกำหนดตัวแปร `is_valid_mode = True/False` แล้วค่อยใช้ `if is_valid_mode:` ก็ได้ — ลองออกแบบดูว่าแบบไหนอ่านง่ายกว่า!)

## 7. แบบประเมินตัวเองก่อนส่ง (Self-Check)

| รายการตรวจสอบ | ใช่ | ไม่ใช่ |
| :--- | :---: | :---: |
| ลองทดสอบค่าขอบ `80.0` และ `79.5` ในตอนที่ 1 แล้วได้ `A` และ `B+` ตามลำดับ | ☐ | ☐ |
| ลองกรอกคะแนน `90` แต่เข้าเรียน `53` ชม. แล้วได้ `มส.` (ไม่ได้ A) | ☐ | ☐ |
| ลองเลือกโหมด `9` ในตอนที่ 2 แล้วโปรแกรมหยุดแจ้งเตือนทันทีโดยไม่แครช | ☐ | ☐ |
| ทดสอบอุณหภูมิ `78°C` เทียบกันระหว่างโหมด `1` (Office) กับโหมด `2` (Gaming) แล้วได้ผลต่างกัน | ☐ | ☐ |
| ไม่ได้ใช้ `for`, `while`, `def`, หรือ `try-except` ในโค้ด | ☐ | ☐ |
| มี comment ภาษาไทยอธิบายแต่ละด่านตรวจสอบชัดเจน | ☐ | ☐ |
| วาด Decision Flowchart ตรงตามลำดับ `if-elif` ในโค้ดจริง | ☐ | ☐ |

> [!warning] ข้อผิดพลาดที่พบบ่อยในใบงานนี้
> - **เรียงเกรดผิด:** เอา `>= 50` ขึ้นก่อน `>= 80` ทำให้ทุกคนที่ผ่านได้เกรด `D` หมด
> - **ลืม `else:` หลัง Validation:** ทำให้พอกรอกคะแนน `55` เตือน Error แล้วโปรแกรมยังไหลลงไปคำนวณเกรดต่อจนพังหรือแสดงซ้อน
> - **เทียบ `"1"` กับ `1` ผิด:** `mode = input(...)` ได้เป็นข้อความ `"1"` ถ้าเขียน `case 1:` จะไม่มีวันเข้าเงื่อนไข
> - **ใช้ `elif` เชื่อมชุดคนละเรื่อง:** เอา `if usage >= 95:` ไปเขียนเป็น `elif usage >= 95:` ต่อจากอุณหภูมิ ทำให้พออุณหภูมิเข้าเงื่อนไขแล้วโปรแกรมข้ามการตรวจ `% CPU` ไปเลย!
